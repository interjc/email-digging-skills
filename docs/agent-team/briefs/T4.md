# T4 brief: synthetic fixtures and their generator

Goal: a deterministic generator `scripts/make-fixtures.ts` and its committed output under `fixtures/`,
covering every format, encoding and anomaly in rule R8 of `docs/design/phase-1.md`, plus
`fixtures/expected.json` stating the exact counts the pipeline must produce. Tests of the reader,
the merge and the demo run are checked against these numbers, so they must be right by construction.

Read `docs/agent-team/briefs/_common.md` first.

Lease: `scripts/make-fixtures.ts`, `scripts/make-fixtures.test.ts`, everything under `fixtures/`.

Design (data-driven, so the expected numbers cannot drift from the data):
- Declare each source as a list of rows in the generator; each row carries the raw cell values and an
  annotation of what it is (e.g. `{ expect: 'valid' | 'empty' | 'invalid' | 'role' | 'typo' | 'legacy' | 'split:3' | 'excluded', email: '<normalized address(es)>' }`).
  `expected.json` is computed from the annotations, never typed by hand.
- Sources (directory names are the source labels; all names, people and addresses fictional):
  1. `shop-alpha` (kind product, consent_basis opt_in): two CP932 CSVs `members_2025-03-01.csv` and
     `members_2025-09-01.csv`, headers `会員ID,メールアドレス,氏名,登録日,メルマガ配信`; dates like `2025/03/01`;
     consent `配信する` / `配信しない` / empty; at least one address whose consent changes between exports;
     names using ①, ㈱, 髙 (CP932-only characters). meta.md declares encoding cp932 and the column mapping.
  2. `cn-delta` (other, unknown): GB18030 CSV `users_2024-12-31.csv`, headers `邮箱,姓名,注册时间,订阅`
     (`是`/`否`), one name containing `𠀀` (U+20000, a 4-byte GB18030 sequence). meta.md: encoding gb18030.
  3. `export-epsilon` (other, unknown): UTF-16LE with BOM tab-separated `contacts_2025-06-30.txt`
     (Excel "Unicode text"), English headers `Email Address	Full Name	Created`; meta.md encoding `auto`, no columns.
  4. `zeta-signup` (event, transactional): UTF-8 with BOM `signup_2025-01-15.csv` with headers that
     need auto-detection (`E-mail,Display Name,Signed Up At,Newsletter`) and meta.md with empty `columns:`;
     plus `extra_2025-01-15.json` (JSON array of objects with keys `mail`, `name`) in the same source.
  5. `event-beta` (event, unknown): `attendees_2023-11-03.xlsx` (sheet `attendees`), headers
     `Email,Name,Registered,Locale`; and `walkin_2023-11-03.csv` (UTF-8) with two title lines before the
     header (`header_row: 3`).
  6. `app-gamma` (product, opt_in): SQLite `app_2025-08-01.db` with table `users(id INTEGER, email TEXT,
     display_name TEXT, created_at TEXT, newsletter INTEGER, locale TEXT)`; newsletter 1/0/NULL; meta.md
     `table: users`, `consent_values: {granted: ["1"], denied: ["0"]}`.
- Anomalies (spread over the sources; every one at least once): full-width `＠` and full-width letters,
  `mailto:`, `<addr>`, `Name <addr>`, zero-width space, mixed case, a cell with 3 addresses separated by
  `;` and `、`, empty cells, invalid syntax (3+ kinds), role addresses (info@, noreply@), typo domains
  `example.con` and `example.co.jo`, legacy mobile dots (`taro..yamada.@example.jp`), Gmail-style
  variants that must stay separate (`hanako.sato@example.com`, `hanakosato@example.com`,
  `hanako.sato+news@example.com`), in-file duplicates, the same person in 3+ sources (cross-source
  duplicates with different raw forms), and one test account `qa-test@example.com` listed in
  `fixtures/overrides/exclude.yaml`.
- `fixtures/overrides/`: `exclude.yaml` (that test account), `typo-decisions.yaml` (accept one typo,
  reject another), `suppressions.yaml` (one manual suppression), `consents.yaml` (empty list).
  Shapes: `Overrides` in `scripts/lib/types.ts`; YAML top level is a list.
- meta.md files follow requirements §4.2 (YAML frontmatter + a `## Notes` section) and `SourceMeta` in
  types.ts. Use the `yaml` package to write frontmatter.
- `expected.json` shape: `{ "sources": { "<source>": { "files": { "<file>": { "rows_read", "empty",
  "invalid", "cells_split", "dup_in_file", "role", "typo_suspect" } }, "unique_emails": n } },
  "after_overrides": { "excluded": n, "typo_accepted": n }, "cross_source_dups": n,
  "contacts_total": n, "overlap": [{ "a", "b", "contacts" }] }`. Counting rules: R1 of the design doc
  (a split cell counts once in `cells_split` and produces one candidate per address; `dup_in_file` counts
  extra occurrences of the same normalized address within one file; `contacts_total` is the number of
  distinct normalized addresses across all sources after exclude and accepted-typo overrides).
- Write files with exact bytes: CP932 / GB18030 / UTF-16LE encoders are not in Node, so encode with
  a small table built from `TextDecoder` (decode every 2-byte sequence once to build a reverse map; for
  GB18030 4-byte sequences, the U+20000 sequence is `0x95 0x32 0x82 0x36`) and verify every written file
  round-trips through `new TextDecoder('<label>', {fatal: true})`. Excel: DuckDB `COPY ... TO '<f>.xlsx'
  (FORMAT xlsx)` after `INSTALL excel; LOAD excel;` (via `@duckdb/node-api`; verified to work). SQLite:
  `node:sqlite` `DatabaseSync`.
- Deterministic: running the generator twice yields byte-identical text files (xlsx/db: identical
  query results). `node scripts/make-fixtures.ts` rewrites `fixtures/sources` and `fixtures/expected.json`.

Test `scripts/make-fixtures.test.ts`: every text fixture round-trips through its declared encoding;
expected.json matches a recount from the annotations; every address in `fixtures/` uses an allowed
domain (`example.*`).

Acceptance: tsc (common), `node scripts/make-fixtures.ts` twice + `git status --short fixtures` showing
no diff between the runs for text files, `node --test scripts/make-fixtures.test.ts`. Paste outputs and
`fixtures/expected.json`.
