# T6 brief: probe, decode, read, detect columns, stage; add-source

Goal: turn the files of one source into staged, normalized rows (`rows.parquet`, `rejected.parquet`,
`stats.json`), and the `add-source` command that probes a new source and drafts its meta.md.

Read `docs/agent-team/briefs/_common.md` first.

Lease: `scripts/lib/meta.ts`, `scripts/lib/read/**` (probe, decode, readers per format, synonyms,
dates, consent values), `scripts/lib/stage.ts`, `scripts/add-source.ts`, and their `*.test.ts` files.

Interfaces: "Module interfaces" in `docs/design/phase-1.md` (meta, read, stage). Types: `SourceMeta`,
`MetaFile`, `FileProbe`, `ColumnMapping`, `StagedRow`, `RejectedRow`, `FileStats`, `SourceStageResult`.
Rules: R3 consent values, R4 encodings (D11: decode in Node, read UTF-8 with DuckDB), R5 dates,
R6 column detection, D13 Parquet, D14 overrides applied at staging (exclude → rejected
`excluded_by_override`; typo accept → email = suggestion, flag `typo_accepted`, status recomputed;
typo reject → drop flag and suggestion, status recomputed).

Being written in parallel (code against the signature; if the file is missing when you need it,
continue with the rest and use it once it appears; report if it never does):

Verified (do not re-check), spike 2026-11-26 with @duckdb/node-api 2.0.1:
- `read_csv('<f>', encoding='cp932', all_varchar=true)` reads ①㈱髙 correctly; `encoding='shift_jis'` fails
  on ①; `encoding='gb18030'` rejects 4-byte sequences (𠀀) → hence D11.
- `new TextDecoder('shift_jis', {fatal:true})` decodes the CP932 sample; `new TextDecoder('gb18030',
  {fatal:true})` decodes 𠀀.
- `read_csv` with `encoding='utf-16'` reads a UTF-16LE BOM TSV.
- Extensions excel, sqlite (sqlite_scanner), json, parquet load after `INSTALL x; LOAD x;`.

Verify yourself first (if different, adapt and report):
- How to get the 1-based data row number in file order from DuckDB (e.g. `CREATE TABLE t AS SELECT * FROM
  read_csv(...)` then `rowid`, or numbering rows while iterating the result). It must match the line
  order of the file, with header/preamble rows excluded.
- `read_xlsx(path, sheet=..., header=true, all_varchar=true)` and how `header_row` > 1 maps for xlsx
  (`range`) and csv (`skip`).

Behavior:
- `loadMeta(dir)`: parse the YAML frontmatter with `yaml`; validate against `SourceMeta`; `source` must
  equal the directory name and match `^[a-z0-9]+(-[a-z0-9]+)*$`; defaults: encoding auto, header_row 1;
  every file listed must exist; files present but not listed (except meta.md, NOTES.txt, meta.draft.md)
  → warning. Errors name the field.
- `probeFile`: format by extension (`.csv`, `.tsv`, `.txt` (tab-separated), `.xlsx`, `.json`, `.jsonl`,
  `.db`/`.sqlite`/`.sqlite3`), encoding (R4), headers, row count, mappings (meta first, then R6).
- `stageSource(meta, {stagingDir, overrides})`: remove and recreate `stagingDir/<source>/`; per file:
  sha256 of the raw bytes, decode, read all rows as strings, map columns, run `normalizeEmailCell` on the
  email cell, build `StagedRow`s (name/locale trimmed, empty → null; dates R5; consent R3 with
  `consent_raw` kept; `raw_fields` = all original columns of the row) and `RejectedRow`s, count `FileStats`;
  write Parquet with DuckDB (flags as a list, raw_fields as JSON text) and `stats.json`. Email column not
  found → throw an error naming the file and the headers seen (masked values never appear in errors).
  Never modify files in the source directory.
- `add-source <name> [--workspace p] [--json]`: validate the name; create `resources/<name>/` if missing
  (print "put the export files here" and exit 0); probe every file; write `meta.md` if it does not exist,
  else `meta.draft.md` (never overwrite meta.md); print per file: format, encoding + how + candidates,
  rows, headers, each mapping with confidence, and up to 3 **masked** sample values per mapped column
  (`maskValue`); list what the human must confirm (auto encodings, mappings < 0.8, consent_basis,
  exported_at guessed from a `YYYY-MM-DD` in the file name).

Tests: per format reader, encoding detection (each R4 branch incl. cp932-vs-gb18030 ambiguity), dates
(R5 table), consent values (R3 incl. meta override), synonyms (R6), meta validation errors, and once
`fixtures/expected.json` exists, a test that stages every fixture source and compares per-file
`rows_read, empty, invalid, cells_split, dup_in_file, role, typo_suspect` and `unique_emails` with it
(staging dir under `os.tmpdir()`, using `fixtures/overrides`).

Acceptance: tsc (common), `node --test "scripts/lib/read/*.test.ts" scripts/lib/meta.test.ts
scripts/lib/stage.test.ts scripts/add-source.test.ts`; plus `node scripts/add-source.ts <name> --workspace
<tmp ws>` on a copy of one fixture source (paste output; it must show masked values only).
