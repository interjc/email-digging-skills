# T2 brief: email normalization module

Goal: a pure, fully tested `normalizeEmailCell(cell): EmailCandidate[]` implementing rule R1 of
`docs/design/phase-1.md`, plus the rule tables it uses. Every later step (staging, merge, reports)
depends on its exact behavior.

Read `docs/agent-team/briefs/_common.md` first.

Lease (create/edit only these):
- `scripts/lib/email/normalize.ts` (export `normalizeEmailCell`, matching `NormalizeEmailCell` in types.ts;
  you may also export small helpers such as `isRoleLocal`, `suggestTypo`, `validateSyntax`)
- `scripts/lib/email/*.ts` helper modules if you want to split
- `scripts/lib/email/normalize.test.ts` (and other `*.test.ts` in that directory)
- `scripts/lib/rules/role-locals.json`, `scripts/lib/rules/domain-typos.json`
  (`{"exact": {"gmial.com": "gmail.com", ...}, "suffix": {".co.jo": ".co.jp", ...}}`)

Verified (do not re-check): Node 26.7 locally, `String.prototype.normalize('NFKC')` turns `＠` into `@`.

Behavior: exactly R1 (steps 1–9). Points that need care:
- Splitting must not break `Name <addr>` or quoted names: extract addresses from such forms first.
- `raw` is the part of the cell the candidate came from, untrimmed of meaning but without separators.
- `email_status` precedence typo_suspect > role > valid; flags sorted, unique.
- Rejected candidates have `email`, `domain`, `status`, `suggestion` = null.
- No I/O, no randomness, deterministic output order (order of appearance in the cell).

Tests (node:test, `node:assert/strict`): one case per R1 step and per flag, including full-width
`ｔａｒｏ＠ｅｘａｍｐｌｅ．ｊｐ`, `mailto:` + angle brackets, `山田 <taro@example.jp>`, zero-width spaces,
`a@example.com; b@example.com、c@example.com`, duplicate parts in one cell, empty/whitespace,
`no-at-sign`, `a@@example.com`, `a@example`, `taro..yamada.@example.jp` (legacy dots, valid),
`info@example.com` and `info+jp@example.com` (role), typo exact (`a@gmial.com`) and suffix
(`a@example.con`, `a@example.co.jo`), role + typo together, Gmail dot/plus variants stay distinct,
uppercase → lowercase.

Acceptance: `./node_modules/.bin/tsc --noEmit -p .` and `node --test scripts/lib/email/*.test.ts`
(paste output). Also run the R1 examples as a table in your report: input → candidates.
