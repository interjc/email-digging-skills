# T5 brief: workspace, config, env, overrides, database, init-workspace

Goal: the foundation every CLI uses (find and guard the workspace, load config/env/overrides, open and
migrate the SQLite database, back it up) and the `init-workspace` command a new user runs first
(requirements §9.1). The guard is a privacy control: no command may run against a workspace that git
could commit.

Read `docs/agent-team/briefs/_common.md` first.

Lease: `scripts/lib/paths.ts`, `scripts/lib/config.ts`, `scripts/lib/env.ts`, `scripts/lib/overrides.ts`,
`scripts/lib/db.ts`, `scripts/lib/errors.ts`, `scripts/lib/cli.ts` (tiny shared arg parsing + exit
helpers: `parseArgs` from `node:util`, `PreconditionError` → exit 2), `scripts/init-workspace.ts`, and
tests `scripts/lib/{paths,config,env,overrides,db}.test.ts`, `scripts/init-workspace.test.ts`.

Interfaces: "Module interfaces" in `docs/design/phase-1.md` (paths, config, env, overrides, db). Types
from `scripts/lib/types.ts` (`PipelineConfig`, `Overrides`, `EXIT`).

Verified (do not re-check):
- `node:sqlite` exports `DatabaseSync`, `StatementSync`, `backup` on Node 26.7; the repo requires >= 22.18.
- Both migrations apply cleanly with `sqlite3` in order 0001, 0002.
- `.gitignore` ignores `workspace/*` except `workspace/.gitkeep`; `git check-ignore -q <path>` works for
  paths that do not exist yet.
- `@duckdb/node-api` 2.0.1: `const db = await DuckDBInstance.create(':memory:'); const c = await db.connect();
  await c.run('INSTALL excel; LOAD excel;')` works for excel, sqlite, encodings; `select version()` → v2.0.1.

Behavior:
- Workspace resolution: `--workspace` flag > `MAIL_PIPELINE_WORKSPACE` (process env, then `.env`) >
  `config.yaml` `workspace` (relative to repo root) > `<repo>/workspace`. `repoRoot()` = directory
  containing this repo's package.json (from `import.meta.dirname`).
- Guard (`requireWorkspace`): the directory and its layout exist and `database/mail-list.sqlite` exists
  (else: "run init-workspace"); if the workspace is inside the repo, `git check-ignore -q
  <ws>/resources/__probe__.csv` and `<ws>/database/__probe__.sqlite` must both succeed (else stop: "the
  workspace is inside the repository but not git-ignored"). Not a git repo → warn only. Paths containing
  `Library/Mobile Documents`, `Dropbox`, `OneDrive`, `Google Drive`, `iCloud` → warning "cloud-synced folder".
- Layout: `resources/`, `overrides/`, `output/{staging,reports,masked,exports}/`, `database/backups/`,
  db file `database/mail-list.sqlite`.
- `loadConfig`: YAML via `yaml`; defaults from `config.example.yaml` values; validate types; unknown keys → warning.
- `loadEnv`: parse `.env` (KEY=VALUE, `#` comments, optional quotes); never log values.
- `loadOverrides(dir)`: the four YAML files of D14; missing file = []; validate each entry
  (emails are normalized with lowercase+trim only here; full normalization happens in staging).
- `db.ts`: `openDb(path, {readonly})` (`PRAGMA foreign_keys = ON`, journal mode DELETE so the db stays
  one file); `migrate(db, dir)` applies `NNNN_*.sql` not yet in `schema_migrations` in order, each in a
  transaction, bootstrapping when the table does not exist; `backupDb(dbPath, backupsDir, keep)` uses
  `VACUUM INTO '<backups>/mail-list-<UTC yyyymmddThhmmssZ>.sqlite'`, prunes the oldest beyond `keep`,
  returns null when the db does not exist.
- `init-workspace [--workspace <p>] [--demo] [--json]`, idempotent, never overwrites:
  1. checks: Node >= 22.18; DuckDB loads, version; extensions excel + sqlite required, encodings optional
     (INSTALL may need network: on failure print the fix); pnpm deps installed.
  2. resolve the workspace and run the git-ignore check (stop with exit 2 if inside repo and not ignored).
  3. create the layout. 4. copy `config.example.yaml` → `config.yaml`, `.env.example` → `.env` when
     missing; if `MASK_HMAC_KEY` is empty in `.env`, set it to 32 random bytes hex (edit only that line;
     never print it). 5. migrate the main db. 6. if `.githooks/` exists and this is a git repo and
     `core.hooksPath` is unset, `git config core.hooksPath .githooks`. 7. `--demo`: create
     `<ws>/.demo/` with its own layout, copy `fixtures/sources/*` into `.demo/resources/` and
     `fixtures/overrides/*` into `.demo/overrides/`, migrate `.demo/database/mail-list.sqlite`; then print
     "demo pipeline run: not wired yet" (another task wires it). 8. print a table: check, result, fix;
     then "Next: add-source <name>". `--json` prints the same as JSON.
- Tests use temp repos/workspaces under `os.tmpdir()` (copy package.json + .gitignore + migrations into
  a temp git repo when testing the guard). Cover: resolution order, guard refusal when not ignored,
  idempotent second run (no overwrite, key unchanged), migrate twice = no-op, backup pruning.

Acceptance: tsc (common), `node --test scripts/lib/{paths,config,env,overrides,db}.test.ts
scripts/init-workspace.test.ts`, and `node scripts/init-workspace.ts --workspace <tmpdir>/ws --json`
run twice (paste both). Do not run it against the repository's own `workspace/` or `.env`.
