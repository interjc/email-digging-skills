# T8 brief: query, mask-data, export, provider interface, Listmonk dry-run

Goal: the read side of the pipeline. `query` answers list questions read-only with masked output;
`mask-data` makes a shareable masked copy; `export` builds the sendable list for a provider as a
dry-run file. These back the `query-list`, `mask-data` and `export-to-provider` skills.

Read `docs/agent-team/briefs/_common.md` first.

Lease: `scripts/query.ts`, `scripts/mask-data.ts`, `scripts/export.ts`, `scripts/lib/query.ts`,
`scripts/lib/masked-copy.ts`, `providers/index.ts`, `providers/listmonk/index.ts`,
`providers/listmonk/README.md`, `providers/README.md`, and tests `scripts/{query,mask-data,export}.test.ts`,
`scripts/lib/{query,masked-copy}.test.ts`, `providers/**/*.test.ts`.

Use (read-only, already committed): `scripts/lib/{paths,config,env,db,cli,errors,mask}.ts`, types
`Provider`, `ProviderContext`, `PushPlan`, `PullResult`, `ProviderList`, `EXIT` in `scripts/lib/types.ts`,
schema and views in `schema/migrations/`, `docs/schema.md`, `docs/masking.md`, `docs/consent-policy.md`,
decisions D2, D16, D24 in `docs/design/phase-1.md`. The merge (T7) is being written in parallel: do not
depend on it; in tests create a temp workspace with `migrate` and insert rows with SQL.

Every CLI: `requireWorkspace()` first (exit 2 on failure), `--workspace`, `--json`, masked stdout.

1. `query [--sql "<SELECT…>"] [--preset <name> …] [--limit N=50] [--out] [--workspace] [--json]`
   - Opens the db read-only (`openDb(path, {readonly: true})` and `PRAGMA query_only = ON`). Accepts one
     statement starting with SELECT or WITH; anything else → exit 1 "query is read-only".
   - Output masking: columns whose name matches email/mail/name/phone/tel/address (and JP/CN equivalents,
     via `maskValue`) are masked; any other value that contains an address is masked with `maskEmail`;
     JSON columns (`raw_fields`, `flags`, `evidence`) are printed with values masked the same way.
   - `--out`: writes the full, unmasked result to `output/exports/query-<UTC stamp>.csv` and prints only the
     path and row count (full values only under exports, AGENTS.md rule 1).
   - Presets (SQL in `scripts/lib/query.ts`): `sources` (rows per source, consent counts), `overlap`
     (pairwise from `v_source_overlap`), `only-in --source A --not-in B` (contacts in A but not B),
     `sendable --list strict|not_blocked` (count + masked sample), `domains` (top 20 domains),
     `status` (counts by email_status and each flag), `consent` (per source × status), `orphaned`.
2. `mask-data [--hash-domain] [--shape] [--workspace] [--json]`
   - Needs `MASK_HMAC_KEY` from `.env` (`loadEnv`); empty → exit 2 "run init-workspace".
   - Writes `output/masked/mail-list-masked.sqlite`: same schema (run `migrate`), all rows copied with
     `contacts.email`, `suppressions.email`, `contact_sources.raw_email`, `contacts.suggested_email` →
     `hmacLocalPart(…, {keepDomain: config.masking.keep_domain && !--hash-domain})`; `email_domain` hashed too
     when the domain is hashed; `name` → NULL; `raw_fields` keys kept, values: address-like → hmac, others
     → "" (null stays null); `rejected_rows.raw_value` → `<redacted len=N>`; consent `evidence.value` kept
     only when it is a consent value (R3 table), else "". Same input + same key → identical output.
   - `--shape`: also writes `output/masked/shape.json` (per source and file: column names, encoding,
     row count, null rate per raw_fields key, counts of each flag/status, reject reasons) — no values.
   - Prints a masked summary and says that only `output/masked/` may leave the machine.
3. `export --provider <name> [--list strict|not_blocked] [--apply] [--workspace] [--json]`
   - `providers/index.ts`: `loadProvider(name)` imports `providers/<name>/index.ts` (default export
     `Provider`); unknown name → exit 1 listing the available directories. No core change is needed to add
     a provider (plugin rule, requirements §11.4).
   - Default list `strict`. `not_blocked` prints a warning that it includes contacts without positive
     consent (docs/consent-policy.md) and requires `--list not_blocked` explicitly.
   - `--apply` in phase 1 → exit 2 "applying to a provider is not available in phase 1; it will require
     explicit human confirmation". Without it, dry-run.
   - Writes a `sync_log` row (`direction push`, `dry_run 1`, counts JSON, status).
   - Listmonk provider (`providers/listmonk/index.ts`): `envKeys` = LISTMONK_URL, LISTMONK_USERNAME,
     LISTMONK_API_TOKEN, LISTMONK_LIST_ID (not needed for dry-run); `pushContacts` writes
     `output/exports/listmonk-<list>-<UTC stamp>.csv` in Listmonk's subscriber import format (header
     `email,name,attributes`; attributes = JSON string with `sources` (array), `flags`, `locale`,
     `email_status`), returns `PushPlan` (`to_add` = rows, `to_update`/`to_remove` = 0 with a note that
     they need the API); `pullSuppressions` throws an Error "not implemented in phase 1".
     `providers/listmonk/README.md`: what it does now, what `--apply` will do later, env keys.
     `providers/README.md`: how to add a provider (interface, env keys, dry-run first, sync_log, keyed by email).

Tests: read-only refusal (UPDATE, DELETE, ATTACH, multiple statements), masking of every output path
(regex: no `@` followed by an unmasked domain label in stdout), each preset against hand-inserted rows
with known answers, `--out` location, mask-data determinism + no raw address or name in the masked db
(scan every text cell), `--hash-domain`, export strict vs not_blocked counts from rows designed to differ
(granted vs unknown vs denied vs suppressed vs orphaned vs typo_suspect), CSV format, sync_log row, unknown
provider, `--apply` exit 2.

scripts/lib/query.test.ts scripts/lib/masked-copy.test.ts "providers/**/*.test.ts"`; `pnpm test`.
