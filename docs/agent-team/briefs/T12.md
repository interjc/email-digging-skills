`providers.ts` exports `damerauLevenshteinOsa(a, b)` and `suggestProvider(domain): string | null`:
1. Return null when the domain is on either list.
2. Candidates = providers at OSA distance exactly 1 from the full domain.

4. That candidate is not at distance 1 from any other provider (`163.com`/`126.com`), else null.
5. Same number of labels, else null. The differing label (the first label where they differ) has at least 5
   characters in the candidate, else null (`qq`, `me`, `163` are too short).

`normalize.ts`: keep the existing exact and suffix table first; only when it gives no suggestion, call
`suggestProvider`. The result becomes the same `suggestion` / `typo_suspect` flag as today.

## B. DNS classification (`dns-check.ts`)

- `export type MailVerdict = 'accepts' | 'refuses' | 'unknown'` and
  `classifyDomain(domain, resolver): Promise<{ verdict: MailVerdict; reason: string }>`.
- `resolver` is an injected interface `{ resolveMx, resolve4, resolve6 }` so tests never touch the network. The
  real one is `new Resolver({ timeout: 3000, tries: 2 })` from `node:dns/promises`, using the host's servers.
  Never call `setServers`.
- Rules (RFC 5321 §5.1, RFC 7505): MX records present → if the only MX is preference 0 with exchange `''`
  or `'.'` → refuses (null MX); else accepts when at least one exchange resolves to A or AAAA, unknown when
  those lookups fail with a temporary error, refuses when every exchange is ENOTFOUND. `ENODATA` on MX → try
  A then AAAA: an address → accepts, none → refuses. `ENOTFOUND` → refuses. `ETIMEOUT`, `ESERVFAIL`,
  `ECONNREFUSED`, anything else → unknown.
- `classifyDomains(domains, resolver, { concurrency = 8 })`: dedupes, caches within the run, caps concurrency.
- Only domains are ever queried; never put a local part into a DNS name or a log line.

## C. CLI `scripts/check-domains.ts [--workspace <p>] [--dns] [--json]`

- `requireWorkspace` first (exit 2 on failure). Holds the workspace lock (it writes a file). Opens the database
  read-only.
- Input: contacts with `email_status = 'typo_suspect'`, `orphaned_at IS NULL`, and no entry yet in
  `overrides/typo-decisions.yaml` (reuse the same "decided" logic as review-report).
- Without `--dns`: every suspect is **ambiguous** with reason "DNS not checked (run with --dns)". No network.
- With `--dns`: classify the typed domain and the suggested domain. **Obvious** = typed refuses AND suggested
  accepts. Otherwise ambiguous, with the reason (typed domain accepts mail; typed domain unknown: timeout;
  suggested domain does not accept mail; ...).
- Stdout: masked only (`maskEmail` for addresses; domains of suggestions may be shown as-is because they are
  providers; the typed domain is shown masked like the rest of the address). Obvious first, then ambiguous.
- Writes `output/reports/domain-check.yaml` with `writeFileInWorkspace` (full values, like
  `pending-decisions.yaml`): a header comment saying "copy the entries you agree with into
  overrides/typo-decisions.yaml", then `obvious:` entries pre-filled `action: accept` with a `note` giving
  the evidence, then `ambiguous:` entries with `action: null` and the reason. It never writes to `overrides/`.
- `--json`: sanitized per value (D32), counts plus masked entries.
- Exit 0 also when there is nothing to check (print "no undecided typo suspects").
- review-report: in the "Typo suspects without a decision" hint, append "(run check-domains --dns to sort them)".
