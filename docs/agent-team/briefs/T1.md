# T1 brief: spec documents

Goal: five English spec documents that a new contributor or agent can follow without reading the
Chinese requirements: `docs/schema.md`, `docs/cleaning-rules.md`, `docs/consent-policy.md`,
`docs/masking.md`, `docs/meta-template.md`.

Read `docs/agent-team/briefs/_common.md` first (no code in this task; the tsc/test commands do not apply).

Lease: exactly those five files.

Sources of truth, in order: `docs/design/phase-1.md` (decisions D1–D20 and rules R1–R8 win where they
are more specific), `schema/migrations/*.sql`, `scripts/lib/types.ts`, `docs/init/REQUIREMENTS.md`
(§4.2, §5, §6, §9.2, §12). Do not invent rules; where these sources are silent, write
"Not decided yet" and list it under "Open questions" at the end of your reply.

Contents:
- `schema.md`: every table and view of the migrations (columns, meaning, who writes it, append-only or
  rebuilt), how a merge updates each table (D3), the sendable views (D2), example queries from
  requirements §5 written as SQL that works on these tables (products A-not-B, pairwise overlap, sendable
  list), the migration rule (AGENTS.md rule 6), and the Postgres porting notes from the 0001 header.
- `cleaning-rules.md`: encodings (R4, D11), email normalization (R1, incl. the rule tables' file paths),
  dates (R5), column detection (R6), dedupe and merge (requirements §6.3, D3, D8, D14, D15), overrides
  files with YAML examples (shapes from `Overrides` in types.ts), and the report contents (requirements §6.4).
- `consent-policy.md`: consent statuses and evidence, default value table (R3), `consent_basis` and
  config `consent.opt_in_bases` / `opt_in_sources`, conflict rule D15, the two lists (D2) and why strict
  is the default (Japan's Act on Regulation of Transmission of Specified Electronic Mail requires prior
  opt-in for marketing email, with exceptions; this is not legal advice; users must check their own
  jurisdiction), suppressions always win, and the paid verification step before sending (requirements §12).
- `masking.md`: which fields count as personal data, display masking (R2) with examples, masked exports
  (`output/masked/`, HMAC with `MASK_HMAC_KEY`, keep_domain option), reports masked by default, fixture
  generation rules (synthetic only, example domains), and that only `output/masked/` may leave the machine.
- `meta-template.md`: the full meta.md template (frontmatter fields from `SourceMeta`/`MetaFile` incl.
  `table`, `query`, `delimiter`, `consent_values`), each field explained, defaults, and a filled example
  using a fictional source with example.jp addresses.

Style: plain, short sentences; tables for field lists; examples only with example.* domains.

Acceptance (run, paste output): `grep -nE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}' docs/*.md | grep -vE '@example\.|\*'`
→ no output; and a checklist in your reply mapping each item above to the heading that covers it.
