community and governance files, and do a consistency pass over the existing docs and skills. This is
documentation only: no code changes.

Read `docs/agent-team/briefs/_common.md` first. Then read `AGENTS.md`, `README.md`, `README.zh-CN.md`,
`CONTRIBUTING.md`, `LICENSE`, `skills/*/SKILL.md`, `docs/*.md`, `providers/README.md`,

## Rules for content

- No real names, email addresses, company or product names from anyone's data, provider URLs or
  account IDs. Use `example.com` / `example.jp` / `example.net` / `example.org` only.
- Commands you document must be ones you ran. Use a temp workspace outside the repository:
  `git archive HEAD | tar -x -C <tmp>/repo`, a `node_modules` symlink, then
  `node <tmp>/repo/scripts/init-workspace.ts --workspace <tmp>/ws --demo`. Never run anything against
  `workspace/` in this repository, and never create `config.yaml` or `.env` in the repository root (they
  already exist there and are the maintainer's: do not touch or read them).
- No state-changing git. The director reviews and commits.
